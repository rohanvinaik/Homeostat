# PREREGISTRATION — §3.2 annotation-recovery validator on the 628 candidate bridges

**Written and committed BEFORE the test code runs (the §13.3 / Phase-2 pattern:
the criterion is fixed on disk before the harness exists, so the result cannot be
massaged). Date: 2026-08-30.**

This is the program's **primary falsifier (§3.2)**: *recovery of known annotation
without having used it.* The §3.3 bridge discovery produced 628 annotation-blind
candidate bridges (degree-matched community-participation p < 0.05, function-blind,
committed `d242e52`, `data/e_i_r/bridge_discovery.json`). Those are hypotheses
(§12.7). This test asks the falsifier's question systematically — not by eye
(eyeballing gene names is the forbidden §12.6/§12.3 move) — with the annotation
set, the statistic, and the decision rule all fixed below before the run.

---

## 1. Hypothesis and its falsifier

**H1 (the program's prediction).** The annotation-blind candidate bridges are
enriched for genes that are *phenotypically pleiotropic* — associated with many
distinct diseases/traits — relative to a matched background, **because a bridge
is a pleiotropic connector (§5.8) and pleiotropy is exactly multi-trait
association.** The structural derivation (PBS + STRING physical + GTEx
co-expression) never saw any trait/disease annotation, so if multi-trait
pleiotropy falls out of the recovered structure, it was recovered without being
used — §3.2 satisfied.

**H0 (null).** Candidate bridges are no more pleiotropic than degree- and
PBS-matched non-candidate genes. The participation metric captured graph topology
uncorrelated with phenotypic pleiotropy; the 628 are not enriched for known
multi-disease genes.

**Decision (fixed now):**
- one-sided permutation **p < 0.05** on the primary statistic → **§3.2 RECOVERED**
  (the pile's annotation-blind bridges recover phenotypic pleiotropy blind).
- **p ≥ 0.05 → NOT RECOVERED**, recorded as such. A null here is an honest,
  publishable result about the pile — not a reason to re-tune the metric (that
  would be method-cycling; the metric is frozen from §3.3).

## 2. The candidate set (FROZEN — no re-derivation)

The **628 genes** with `degree_matched_p < 0.05` from §3.3 bridge discovery. The
full per-gene score table (all 13,800 scorable genes: degree, participation,
pbs_weight, p) is regenerated by the **same deterministic code path** as §3.3
(`bridge_discovery` functions; label propagation is deterministic, sorted
tie-break) and persisted to `data/e_i_r/bridge_scores_full.tsv.gz` so candidates
AND background come from one auditable artifact. Reproducibility check: LRRK2 must
land at rank 300, p = 0.024 (matches the committed `bridge_discovery.json`); if it
does not, STOP — the derivation drifted.

- **Candidates:** the 628 genes with p < 0.05.
- **Background pool:** the remaining 13,172 scorable genes (deg ≥ 2, p ≥ 0.05).

## 3. The annotation — pleiotropy (PRIMARY, declared CLEAN)

**Source:** the GWAS Catalog bulk associations file already in the repo
(`data/network/gwas-catalog-download-associations-alt-full.tsv`, same primary
source as §13.4). **Per-gene pleiotropy = the number of DISTINCT EFO-mapped trait
URIs** (`MAPPED_TRAIT_URI`) a gene (`MAPPED_GENE`) is associated with across the
whole catalog. Distinct URIs (not free-text `DISEASE/TRAIT`) so synonymous trait
spellings do not inflate the count. A gene with no association row → pleiotropy 0
(a real signal: never phenotype-associated).

**Why this is the CLEAN, independently-recovered channel (§10.2).** Trait/disease
associations were **not used anywhere in the derivation**: §3.3 used only PBS
(allele frequency), STRING *physical* edges, and GTEx co-expression. Phenotype
pleiotropy is a downstream, phenotype-level annotation the recovery procedure
never saw. It is the legitimate "recovery of known annotation without having used
it," not a graph-recovering-itself artifact.

**Gene-symbol join:** exact HGNC symbol match between the score table (STRING /
refGene symbols) and `MAPPED_GENE`. Multi-gene GWAS rows (comma/x-separated
`MAPPED_GENE`) are split; each named gene gets credit for that trait URI. Symbols
absent from the catalog → 0.

## 4. The statistic and the matched null (FROZEN)

**Primary statistic:** difference in **mean pleiotropy**,
`Δ = mean_pleiotropy(candidates) − mean_pleiotropy(matched null draw)`,
one-sided (H1: candidates greater).

**Matched null (degree- AND PBS-matched, §13.4's lesson made structural).** For
each candidate gene *c*, its eligible background matches are:
`{ g in background : 0.8·deg(c) ≤ deg(g) ≤ 1.2·deg(c)  AND  |pbs(g) − pbs(c)| ≤ 0.02 }`
(±20% degree band = the LRRK2-gate null; ±0.02 PBS-weight band). One null draw =
sample one match per candidate **without replacement within the draw**
(deterministic RNG, `random.Random(20260830)`); its statistic is the mean
pleiotropy of the 628 sampled genes. **N_PERM = 10,000** draws → null distribution
of the mean.

- Candidates whose eligible-match pool is empty are **dropped** and their count
  reported (honest; not silently matched loosely).
- **p = (#{null_mean ≥ observed_candidate_mean} + 1) / (N_PERM + 1)** (add-one).

This controls the two confounds §13.4 taught us: hub genes have more STRING edges
(→ degree, matched) and the PBS axis is the differential-selection prior
(→ pbs_weight, matched). The signal that survives is pleiotropy in excess of what
degree + differential-selection-rank alone would produce.

## 5. §10.2 contamination declaration — what counts, what is excluded

| annotation | in derivation? | verdict |
|---|---|---|
| **GWAS multi-trait pleiotropy** (this test) | **No** — trait data never used | **CLEAN. Primary.** |
| STRING / Reactome pathway or complex co-membership | **Yes** — STRING physical IS the graph | **EXCLUDED (self-recovering).** |
| GTEx co-expression module membership | **Yes** — GTEx co-expr IS in the graph | **EXCLUDED (self-recovering).** |
| Hand-curated clearance/resolution gene list | function annotation, hand-picked | **SECONDARY / exploratory** (§6) — reported, NOT the falsifier. |

## 6. Named residual confound (declared, not eliminable here)

**Study bias.** Well-characterized genes accrue both more STRING physical edges
AND more GWAS trait associations. Degree-matching absorbs much of this (STRING
degree tracks study intensity), and PBS-matching is orthogonal to it, but it is
not fully eliminable with these data. It is named here so the result is read with
it in view: a positive result is "pleiotropy in excess of degree+PBS-matched
chance," which is degree-conditioned but not study-bias-proof. The honest tightening
(a study-intensity covariate, e.g. per-gene PubMed count) is a future refinement,
not a gate on this run.

## 7. Pre-specified sensitivity analyses (declared now; secondary)

1. **Candidate-set size sweep:** repeat the primary test with candidates = top-100
   and top-300 by p (in addition to the primary 628). Reported as robustness, not
   as the decision.
2. **Leave-the-famous-gene-out:** remove LRRK2 from the candidate set and re-run.
   The signal must not be carried by the one famous bridge; if the enrichment
   collapses without LRRK2, say so.
3. **Clearance/resolution exploratory set** (§6): a small preregistered gene list
   — efferocytosis/autophagy/SPM-biosynthesis (e.g. MERTK, GAS6, ELMO1, ABCA1,
   ALOX5, ALOX15, ALOX15B, LGMN, ATG7, RUBCN) — is the §1.3/§6.7 "ama"
   clearance category. Report whether candidates are enriched for it, flagged
   **exploratory and contaminated** (hand-picked, function-derived, small n): it
   is a lead, never the falsifier.

## 8. What passing and failing each mean

- **PASS (p < 0.05):** the annotation-blind pile recovers phenotypic pleiotropy it
  never used — the §3.2 falsifier holds; the 628 become defensible hypotheses
  (still §12.7, still §12.4-bounded: no dynamics, not established mechanism).
- **FAIL (p ≥ 0.05):** the participation metric does not recover multi-trait
  pleiotropy on this pile. Recorded honestly; the candidates stay unvalidated.
  Not a prompt to tune the metric.
